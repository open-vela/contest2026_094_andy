# 故障排查手册（症状 → 假设 → 检查 → 处理）

> 用法：先按症状定位到小节，再逐条验证。每条都是真机上出现过的，不是理论清单。
> 通用原则：**先证明日志/ELF/镜像与被测对象是同一份**，再开始分析；否则会在错的代码上推理。

## 1. 烧录与启动介质

| 症状 | 先查 | 处理 |
|------|------|------|
| 烧录工具在写 SPL/updater 阶段失败（no CSW / Device lost），换线换电脑无效 | 失败点是在**自研代码之前**还是之后 | 失败在预编译 bootloader 阶段 → 先比对该产物的 SHA256 是否与官方一致（排除"拿错文件"），再核对镜像配置里 loader 的 load/entry 地址与分区/内存配置 |
| 明明改了代码，烧录后行为不变 | 打包脚本是否用了旧产物 | 打包前清产物目录；**显式传板名与芯片名**（不要让脚本从 `.config` 猜）；核对产物时间戳与哈希 |
| 镜像生成"失败"但整体退出码为 0 | 最终 `.img` 是否真的产生 | 某些可选后处理步骤（如稀疏镜像转换）失败是非致命的，确认目标文件存在即可 |
| 加载地址与代码不匹配 | 链接脚本 / ELF 入口 / 打包描述 / raw 二进制四处地址 | 见 `boot_and_core.md` 第 1 节；改链接脚本后必须重新对齐 |

**区分原则**：烧录阶段的失败如果发生在"预编译产物"环节，和你的应用代码无关；不要在应用代码里找原因。

## 2. 启动：完全没有日志

按顺序排除（每一步都能独立判定）：

| # | 假设 | 检查 | 处理 |
|---|------|------|------|
| 1 | 启动器没跳到我们的入口 | 在入口汇编第一条直接写串口发送寄存器 | 出字符 → 跳转与串口基址都对；不出 → 查地址链 |
| 2 | 串口基址/时钟/引脚错 | 对照手册的基址、时钟门控、复用号 | 修正并重试（不要重配前级已配好的串口） |
| 3 | 中断/定时器基址错导致在 `clock_initialize()` 挂死 | 用逐级 marker 定位停在哪一步 | 核对外设基址（写错是静默死）；见 `boot_and_core.md` 第 3 节 |
| 4 | 早期代码用了不可用的机制（锁、堆、状态位） | 早期路径是否调用 `spin_lock`/`kmm_*`/等 TX 状态位 | 改成无锁直写、不等状态位 |
| 5 | 配置把可用路径关掉了 | 生成的 `.config`（不是 defconfig） | 见第 6 节 |

## 3. 启动：有日志但起不来

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| 启动器打印 `Run APP` 后回到自己的命令行 | OS 被搬到错误地址/入口 | 比对打包描述的 load/entry 与 raw 二进制首地址 | 统一为实际入口地址 |
| 停在 `nx_start` 之前/之后，无进一步输出 | 中断控制器或 tick 基址错 | 加逐级 marker；核对基址宏派生值 | 修正基址 |
| 第一次 `zalloc` 就卡死（反汇编首条是 CSR 访问） | 开了一个语义不匹配的内核选项（如在目标核上错误的"关中断用 CSR"选项） | 看反汇编 + 看项目文档是否注明"故意关闭" | **去掉该选项**；不要因为"名字看起来应该开"就加回去 |
| 崩溃现场 `sp` 不在当前任务的栈区间内 | 上下文保存/恢复被污染（常见于 FPU/ABI 配置与工具链不一致） | 打印 `g_running_task`、`sp`、栈区间；核对 `-march/-mabi` 与内核 FPU 选项 | 使二者一致，改完**干净重建**再验证 |
| 链接溢出 | 固件太大 | 看链接错误字节数 | 关掉非必要应用、加大堆余量前先确认布局，或调整分区 |

## 4. 异常与崩溃

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| trap 里死循环，`ecall` 与中断都不派发 | `mcause` 解码错（高位未屏蔽）导致 IRQ 号越界 | 打印原始 `mcause`，与手册编码核对 | 先取低位再按内核规则加异步偏移 |
| `irq=1`（instruction access fault），`epc/ra` 是低地址 | 跳到未初始化/被覆盖的函数指针 | 用 `addr2line`/反汇编定位 `epc` | 找谁覆盖了指针/结构体 |
| `irq=5/7`（load/store fault），伴随 `tval` 小值 | 内存被踩或堆耗尽 | 反汇编现场函数、看是否有"空 task_info" | 检查内存占用（如某应用把 SRAM 吃满，heap 只剩几百字节）；必要时关应用或加大堆并加 `ASSERT` |
| 只在某个命令/按键时崩 | 该路径上的空回调 | 检查 stop/pause/resume 之类回调是否为空实现 | 补实现或避免调用 |
| 收尾阶段指针变成小值（如 `tail=0x8`） | 缓冲被 DMA 收回后又被使用 | 检查完成路径顺序 | 先停外设、归还缓冲，再报告完成 |
| 打了诊断打印后行为变化 | 插桩改变了时序/栈 | 去掉插桩复测 | 诊断必须在结论确认后全部移除；**不要包住调度/异常核心** |

## 5. NSH 与串口交互

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| 有横幅但打不了字 | 只发不收：读路径/中断未生效 | 输入时是否有 RX 中断计数 | 修 RX 中断使能与分发 |
| 能收但 `write()` 卡住 | TX 完成中断/缓冲排空逻辑不对 | 是否依赖不可靠的 TX 状态位、是否有 fake TX 中断 | 让 `txint(true)` 直接推进发送队列（参考同内核的串口实现） |
| 日志输出到不存在的设备 | `SYSLOG_DEVPATH` 与驱动注册节点不一致 | 对照驱动注册的节点名 | 改配置；注意可能有多处需要一起改 |
| 交互需要按回车才响应 | 串口处于 canonical 模式 | 看注册时是否强制 `ICANON` | 需要逐字符交互时改用非 canonical |
| 内置命令不存在 | Kconfig 选项未启用，或被其它选项挡住 | 看生成的 `.config` 与 builtin 表 | 开对应 app 选项；注意某些 shell 功能被别的选项（如环境变量支持）间接禁用 |
| 命令 `help` 里有、执行却报 not found | shell 直执行路径漏掉内置命令表的第 0 项 | 该命令在 builtin 列表中的索引 | 改回走文件系统 app 路径，或修正索引判断 |
| 网络/文件系统工具"不存在" | 精简配置同时裁掉了命令与 procfs 信息项 | 生成的 `.config` | 显式打开所需命令与 procfs 项 |
| 起不来或某命令一跑就 fault，`tval` 是小偏移（如 `0x18`） | 启动堆耗尽（SRAM 被应用占满），现场读到空结构体 | 打印 `_sheap`/`_eheap`；反汇编现场函数访问的结构体 | 关掉占用大的测试应用，留出堆余量，并加**链接期最小堆断言** |

## 6. 构建与配置"不生效"

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| defconfig 里加了选项但行为没变 | 依赖不满足被静默丢弃 / 菜单没被 source / 增量构建沿用旧配置 | 看生成的 `.config` 里该符号是否存在（没有 `=y` 也没有注释行，说明 Kconfig 里根本没这个选项） | 补依赖、`source` 菜单、删构建目录做**干净重建** |
| 加了源文件但没被编译 | 构建清单未同步 | 对比 `Make.defs` 与 `CMakeLists.txt` | 两边都加；用 `bsp_scan.sh` 核对 |
| 配置期报 `arch//include` 之类空路径 | 芯片名没进内核的架构映射，落到 dummy | 看构建目录下的 dummy Kconfig / 生成变量 | 补映射或走自定义芯片机制 |
| 改了栈大小/堆大小没效果 | 同"选项没生效" | 同左 | 干净重建后再测 |
| 分析的现象与代码对不上 | 日志/ELF 不是同一份构建 | 比对构建时间戳、符号地址、SHA256 | 先重建、重新烧录，再分析 |

## 7. 设备节点与注册

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| 节点不出现 | 注册代码没被调用 / 被条件编译掉 / 返回值被忽略 | board bringup 里的注册日志与返回值 | 补注册调用与错误日志；核对 Kconfig 开关 |
| 注册失败，只有一个数字错误码 | 把 errno 记错了，排查方向就错了 | 打真实 errno（如 `-110` 是超时，`-100` 不是） | 先确认真实 errno，再按 errno 语义排查 |
| 打开设备成功但没有数据 | 只到"节点存在"（`device`），没到数据面（`data`） | 按 `verification_and_delivery.md` 的判定标准做数据面测试 | 不要用节点存在替代数据验证 |

## 8. 存储与文件系统

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| MTD/块设备"打不开" | 把它当字符设备 | 该节点类型 | 通过 MTD/块设备注册表访问，不要用应用层 `open()` |
| 写文件返回成功但内容是空/短 | 写满（ENOSPC）被吞掉 | 写入字节数是否恰好等于剩余空间；看真实 errno | 传播 write/fsync/close 的真实 errno；换到有空间的介质；命令里给出明确失败 |
| 报"无数据"但文件其实写不进去 | 写满伪装成 `ENODATA` | 写入量 vs 剩余空间 | 同左：错误码要穿透到上层 |
| `mount` 失败/EIO | 介质格式、时钟相位、上电时序 | 换一张已知良好的卡、确认相位参数 | 分步验证：块设备识别 → 分区 → 挂载 |
| 明明挂载失败，容量查询却有数 | `statfs` 命中了父文件系统 | 挂载点是否真的挂了东西 | 用专门的测试文件判断，不要用容量查询判断挂载成功 |
| 挂载报 `EEXIST` | 挂载点已被 `mkdir` 创建 | `mount()` 是否自身创建挂载点 | 删掉预创建的目录；挂载点不要放在另一个已挂载文件系统里 |
| 占用/删除的实例号对不上（`no such device or address`） | 控制器实例 → 设备号映射漏改 | 搜全部映射点 | 一次改全；实例区分"卡槽"与"SDIO 外设" |
| 整盘读不到分区 | 只看了第 0 扇区 | 是否 dump 过 MBR 偏移处的分区表 | 优先挂载分区节点；整盘失败不要提前返回 |
| 重启后文件消失 | 挂载的是 RAM 文件系统或没写回 | 挂载点来源与分区 | 确认分区与挂载配置 |

## 9. 显示、触摸、按键

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| 背光亮但无画面 | 背光早于显示引擎稳定；格式/stride 错 | 背光使能时序、像素格式 | 加延迟；先跑纯色填充 |
| 画面闪烁 | 每帧重提交显示引擎配置 | 刷新路径 | 开机配置一次，刷新只做 cache 维护 |
| 触摸状态恒为 0、INT 不变 | 配置未真正下发 | 产品 ID 能读但状态寄存器不动 | 按厂商复位/配置序列重做，校验和要正确 |
| 触摸位置偏移 | 方向/分辨率配置 | 配置块参数 | 按面板几何重写配置 |
| 触摸设备打不开 | 单读者限制 | 是否有别的进程占着 | 先关掉诊断命令 |
| 按键立刻触发异常 | 误判成配置缺失并开启了一个"故意关闭"的选项 | 项目文档/注释/提交历史 | 回退该改动；先确认原设计意图 |
| ADC 方向键注册超时 | 使能顺序/flush/触发模式 | 对照参考实现 | 修正使能顺序与单次触发，轮询就绪位 |

## 10. 音频

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| tone/播放命令挂死 | 缓冲队列无人消费 | 是否只有入队没有消费线程 | 加独立低优先级消费线程，入队与唤醒同临界区 |
| 生成音卡顿/欠载 | 逐样本浮点运算太慢 | 是否用了 `sinf()` | 改定点波形 |
| 采集"启动成功"但没有数据 | DMA 读到 0 | 描述符字段、cache 维护 | 见 `dma_cache_irq.md`：先查 cache，再看使能顺序 |
| 只有一次数据后停住 | 描述符链未闭合/单缓冲 | 描述符链接方向 | 双向链接的循环描述符 |
| 采集结束崩溃 | 完成顺序错 | 收尾路径 | 先停外设、归还缓冲，再报告完成 |
| WAV 为空或过小 | 写满/格式封装错 | 输出体积与剩余空间 | 传播 errno；换到有空间的介质 |
| 命令显示已停止但器件仍在工作 | 停止路径没真正等到线程/硬件退出 | flush 返回成功是否被当成"线程已退出"；底层是否真的关掉功放/输出 | 先关功放再等底层锁；不可靠的 stop 路径宁可不提供 |
| 播放时 UI 按键失灵/画面卡顿 | 播放线程优先级过高饿死 UI | 各线程优先级与 CPU 占用 | 让 UI 优先级高于播放线程，做优先级分层 |

## 11. 网络

| 症状 | 假设 | 检查 | 处理 |
|------|------|------|------|
| PHY ID 读不到 | MDIO 时序/复位/引脚 | MDIO 读写、PHY 复位电平与保持时间 | 先保证 PHY ID 正确 |
| PHY ID 正常但 link 一直 down | 读得太早 | 复位后是否立即判断 | 加有界等待，打印自协商寄存器 |
| 有网卡但拿不到 IP | 链路未 up / DHCP 未启动 | link 状态、DHCP 配置 | 先链路、后 DHCP |
| 能 ping 但 HTTP 失败 | 应用层/服务端问题 | 客户端命令返回码 | 分层排查，不要把应用问题记成驱动问题 |
| Wi-Fi 固件无响应 | 供电/总线/固件下载/消息链路 | 逐步检查 CMD5 → CCCR → 功能使能 → CMD53 → 固件校验 → 启动 | 每一步都要有可读证据 |
| Wi-Fi 只能手工命令跑 | 缺 netdev/RX 泵 | 是否有 `wlan0` 与后台接收 | 先注册 netdev 与接收泵，再谈上层命令 |

## 12. 元规则：如何避免错误结论

- **先对齐证据**：确认串口日志、ELF、烧录镜像来自同一次构建（时间戳/符号地址/SHA256）。
- **只信可验证的事实**：符号是否存在、反汇编、寄存器回读值、文件长度/CRC、中断计数。不要只信函数名或"应该如此"。
- **errno 要抄准**：把 `-110` 记成 `-100` 会让整个排查方向偏掉。
- **区分层次**：抽象层错误会被上层掩盖（例如"配置下发失败"表现为"状态不动"）；先在最底层证明链路通。
- **参数正确但顺序错**也会失败："每个寄存器都写对，但写的顺序不对"是常见根因（使能顺序、完成顺序）。
- **配置里没有的选项不等于配置缺失**：先查文档与历史，确认是不是**故意关闭**；"打开后故障能稳定复现"才是证据。
- **允许结论是"未定论"**：把不确定的部分明确标出来，比给一个错误根因有价值。
- **诊断代码要清理**：插桩/打印在确认结论后全部移除并复测；否则会把插桩引入的时序变化当成真实行为。
- **返工要记录**：每次推翻之前的结论，写下"原结论 → 新证据 → 新结论"，这是后面避免重犯的关键。
