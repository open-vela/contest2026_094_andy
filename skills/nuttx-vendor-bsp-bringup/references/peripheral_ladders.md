## 1. 存储：QSPI NOR + MTD + LittleFS

**阶梯**
1. 控制器时钟/复位；pinmux 到 4 线模式；
2. 读 JEDEC ID（证明总线 + 引脚 + 模式都对）；
3. 读 SFDP 拿几何信息，与手册容量核对；
4. 注册 MTD（whole flash 只读 + 分区子设备）；
5. 解析镜像头里的分区表，确认分区边界；
6. 挂载 LittleFS 分区到挂载点；
7. 测试命令：`info`（ID/几何/分区）→ `read`（有界 hexdump）→ `verify`（两次读 CRC32 比对）→ `fs write/check`（跨 reboot 保持）→ `clear`。

**坑**
- **defconfig 写了选项却没生效**：常见三因叠加——① 依赖不满足（例如某个 FS 选项依赖另一个未开的架构选项），Kconfig 会**静默丢弃**；② 芯片 Kconfig 没有 `source` 到 HAL/驱动菜单，选项根本不存在；③ 增量构建沿用了旧配置。排查要**看生成的 `.config`，不是看 defconfig**，并做一次干净重建。
- **`/dev/nor0` 打不开**：MTD 设备是 inode 而不是字符设备，应用层 `open()` + `BIOC_GEOMETRY` 不适用；要通过 MTD 注册表拿到设备再调用其 `read` 回调。
- **挂载点由 `mount()` 自己创建**：预先 `mkdir` 会得到 `EEXIST`；挂载点也不能落在另一个已挂载文件系统里面（例如挂在 `/data/sdcard` 下），要挂到根下的独立目录。
- **未挂载时不要相信容量查询**：`statfs`/`info` 会命中父文件系统，报出父 FS 的容量，看起来"挂载成功了"。判定"是否真的挂上了"要用挂载点内容/专用测试文件。
- **写满会伪装成其它错误**：出现过 `-ENODATA`（"无数据"）实际是文件系统写满（写入字节数恰好等于剩余空间）。write/fsync/close 的 `ENOSPC` 一定要向上传播，否则排查方向会被错误码带偏。
- **两本独立的空间账**：Flash 分区大小 ≠ 运行时 SRAM。腾 NOR 分区不会给 RAM 让出空间；看 `_sheap`/`_eheap` 与链接期最小堆断言。
- 文件系统的页/擦除粒度要与 MTD 几何一致；首次挂载失败时先确认几何，不要随手 autoformat。
- 测试命令**不要提供裸写**：只允许操作自己的测试文件，绝不碰 bootloader/环境变量/系统分区。
- 判定标准用**双读 CRC32 一致**，不要用"读出来了"。

## 2. 存储：SD/MMC + FATFS

**阶梯**
1. 选择正确的控制器实例（不同实例接不同器件：卡槽 / SDIO 外设）；
2. 时钟频率与采样/驱动相位参数（这些常是板级调参项）；
3. 4 位总线、上电时序、卡检测；
4. 注册块设备（`/dev/mmcsdN`）；
5. 挂载 FATFS 到挂载点；
6. 测试：`info`（确认是块设备 + 容量）→ `write` → `check` → `reboot` → `check` → `clear`。

**坑**
- **控制器实例要分清**：同一颗 SoC 上不同 SDMC/eMMC 实例接不同东西（TF 卡槽 vs SDIO 外设）。把 TF 从实例 1 换到实例 0 时，设备号/minor 的映射要在**所有出现的地方**同步改，漏一处就报 `no such device or address`。挂在 SDIO 上的模组不应注册成 `/dev/mmcsdN`。
- **时钟分两段**：识别阶段用低速（ID 模式，通常 < 400 kHz），识别成功后再切传输速率；采样/驱动相位是板级调参项。
- **"位宽配置"不等于"已切到 4 位"**：`BUSWIDTH4` 之类可能只是能力位；SDIO 的实际位宽还要通过功能寄存器（CCCR 的 bus interface control）配合驱动设置，否则会一直停在 1 位。
- **ISR 与轮询争同一个状态位 = 偶发超时**：出现过中断处理里抢清"数据完成"标志，而数据路径正在轮询该位，且全局中断模式让所有控制器默认打开该中断。修法是普通卡不注册该中断、纯轮询，或在 HAL 层默认关闭，handler 只确认真正属于它的中断源。
- **错误码会随复位进展而变**：`-EIO` 变成稳定的 `-ETIMEDOUT` 说明复位路径已经好了，问题转移到了等待/中断路径——这是有效的定位信号，不要因为"错误码变了"就重新从零怀疑。
- **注册 API 返回 OK ≠ 节点真的存在**：控制器挂载/注册函数在 `-ENODEV` 时也可能返回成功；用卡前要有重试/重探测路径，并以"节点可访问"为准。
- **分区表要读对位置**：整盘第 0 扇区只有 `55 aa` 不等于卡坏；MBR 分区表在固定偏移处（如 `0x1be`），要 dump 出来看。优先挂载分区节点（如 `/dev/mmcsdNp1`），整盘挂载失败时不要提前 return，继续尝试分区。
- 挂载耗时较长，放在 **worker 线程**里做，不要阻塞 board bringup——同步在 late init 里挂载会导致"有日志但没有 `nsh>`"。
- 块设备节点同样不能靠应用层 `open()` 校验；要用文件系统路径验证。
- 拔卡前先卸载；热插拔支持需要额外的卡检测中断，未实现前不要假装支持。
- 修改 defconfig 里某一类设备的时钟，可能影响另一类（同一控制器族的共享参数）。

## 3. 显示：LVDS/DE framebuffer 与背光

**阶梯**
1. 显示引擎/接口时钟与复位；
2. 接口引脚（LVDS/RGB/MIPI）pinmux 与通道映射；
3. 面板时序参数（分辨率、前后肩、极性）；
4. framebuffer 内存：位置、大小、stride、像素格式；
5. 注册 framebuffer（`/dev/fb0`）；
6. 背光/面板使能 GPIO，**在 DE/接口稳定后再拉高**（需延迟）；
7. 测试命令：色条/图形，检查颜色顺序、分辨率、格式；
8. 再上 LVGL 等 UI 框架。

**坑**
- **时序**：背光使能早于显示引擎稳定会出现"亮但不显示/花屏"。延迟要与参考配置一致（例如 DE 启动后 20 ms）。
- **显存可能在外扩内存里**：确认容量与地址；外扩内存通常不参与系统堆，别让 heap 误用。
- **刷新闪烁**：常见原因是每帧重新提交显示引擎配置；正确做法是开机配置一次，之后只做 cache 维护/刷新。
- 若平台没有按地址精确 clean 的能力，只能整片 flush，注意粒度与成本。
- framebuffer 上电通常是黑的：判断显示效果前必须先跑一次填充/色条命令。

## 4. 输入：电容触摸

**阶梯**
1. I2C 控制器在线（能读写任意寄存器）；
2. 触摸芯片复位/中断引脚配置；
3. **探测从地址**：同一颗芯片在不同固件/上电时序下可能枚举到不同地址；
4. 读产品 ID（证明协议与地址正确）；
5. 写完整配置块（分辨率、点数、方向），并写入**校验和**；
6. 读状态寄存器，确认出现"就绪帧"；
7. 读坐标/点数帧，验证触点数量与坐标范围；
8. 中断路径：INT 下降沿 → ISR 只置位 → worker 侧读 I2C；
9. 注册标准 input 设备；
10. 测试：原始多点诊断 + 标准 `getevent` 事件流。

**坑**
- 只读产品 ID 成功、状态始终为 0、INT 引脚无变化 → 说明**配置没有真正下发**（地址/复位序列/校验和三者之一错）。要按厂商给的**复位与配置顺序**完整走一遍，不能只写几个寄存器。
- 坐标需要方向/宽高配置配合；配置错会出现"能报事件但位置不对"。
- 标准输入节点通常**只允许一个读者**：诊断命令与 UI 测试不能同时打开；关闭时打印的中断计数（`irq > 0`）是判断中断路径真的工作的证据。
- ISR 里不要做 I2C（会阻塞/死锁）；用 worker，并加一个低频轮询兜底漏掉的中断边沿。
- 触摸 INT/RST 引脚常与其它功能复用，冲突要在文档里明确。

## 5. 输入：按键与 ADC 键盘

**按键（GPIO）**
- 阶梯：GPIO 输入 + 上拉 → 双边沿中断 → 注册到标准 button upper half → 去抖（如 30 ms）→ 测试按下/抬起各一次；
- 坑：有效电平（低有效）、引脚与其它功能复用（如与 I2S 时钟冲突）、按键设备与电源管理要约定谁持有 IRQ（唤醒测试前必须先释放）。

**ADC 键盘（电阻梯）**
- 阶梯：ADC 模块使能 → 校准 → 采样 → 把原始值按区间映射为方向 → 注册第二个按键设备；
- 坑：
  - **使能顺序**：FIFO 阈值、触发模式、flush 时机要与参考实现一致，否则"转换被丢弃"，注册时报超时（注意区分 errno：`-110 ETIMEDOUT` 是超时，不要记成别的）；
  - 每次转换前是否需要 flush，取决于触发方式；只在异常路径 flush 更稳妥；
  - 轮询就绪位再取值，不要盲等固定延时；
  - 判定要**连续 N 次分类一致**再切换状态，再叠加框架去抖，避免抖动误触发；
  - 与其它功能（如某串口 CTS）共用引脚时要显式取舍。

## 6. 控制：看门狗 / RTC / PWM

**看门狗**
- 阶梯：时钟源（常见 32 kHz）→ 时钟门控寄存器 → 复位位 → 读超时 → 注册标准 watchdog 设备 → 先做喂狗测试 → 再做复位测试；
- 坑：复位测试必须有显式确认参数（避免误触发）；复位后要能从 NSH 重新起来才算通过；记录清楚时钟/复位位/中断号。

**RTC**
- 阶梯：电池域时钟 → 计数器读取 → 设置时间（等待初始化完成位）→ 闹钟中断 → 掉电/纽扣电池保持；
- 坑：设置时间要轮询"初始化完成"，不能写完就读；它可以作为系统实时时钟源而不注册 `/dev/rtc0`；复位保持与断电保持要分开验证（含取下主电源、保留纽扣电池的测试）。

**PWM**
- 阶梯：引脚复用 → 频率/占空比 → 注册 PWM 设备 → 输出到目标器件；
- 坑：目标器件常有**规定频率**（例如蜂鸣器电路要求 4 kHz）；命令的每条退出路径都要 `PWMIOC_STOP` 再关闭，否则关掉命令后器件还在响。

## 7. 音频：播放与录音

**播放（DSPK/PA）**
- 阶梯：音频时钟 → 数据引脚 → 功放使能 GPIO（注意有效电平）→ 标准 PCM 设备 → 生成音测试 → WAV 播放；
- 坑：
  - `nxplayer` 的 tone 路径会经过 PCM 解码器；若解码器要求 RIFF 头，需要通过 `AUDIOIOC_CONFIGURE` 显式下发几何信息（采样率/位宽/声道）让解码器走 raw 透传。不要用全局 `RAW` 开关去解决，那会把普通 WAV 的文件头也一起送进扬声器；
  - 生成音用**定点三角波**代替逐样本 `sinf()`：软浮点核上会因计算太慢导致缓冲欠载；
  - 播放缓冲队列出现"有 FINAL 缓冲但没有人继续入队"的悬挂：需要一个独立的消费线程（入队与唤醒放在同一临界区），否则命令直接挂死；
  - **停止路径比开始路径更容易出错**：同步 join + 定时消息 + "flush 返回成功就当线程已退出"这三件事叠加，会出现"命令显示已停止、声音还在响"。可靠的停止顺序是**先关功放（PA），再等底层发送锁**；如果 stop 会长时间阻塞（例如等待 CPU 推送锁），宁可去掉这条路径也别让 UI 卡住；
  - 上层要用**异步启动结果**：底层启动失败若不回传，UI 只能靠超时（表现为 "start timeout"），会被误判成内存或时钟问题；
  - **线程优先级**：播放线程若被设到很高的实时优先级，会饿死 UI/控制线程，表现为"按键失灵 + 画面卡顿"。让 UI 优先级高于播放线程，或显式做优先级分层。

**录音（PDM/DMIC + DMA）**
- 阶梯：DMIC 时钟/数据引脚与复用号 → DMA 请求/通道 → 循环描述符（对齐、双向链接）→ cache 维护 → 注册 PCM 录音设备 → 用标准录音 API 采集 → 封装 WAV；
- 坑：见 `dma_cache_irq.md`。核心三条：**"CPU 侧都对、DMA 读到 0"= cache 维护错**；**使能顺序错 → ADDRESS_REQUEST**；**COMPLETE 之后要先停外设/归还缓冲再报告**。
- `pause`/`resume` 等回调**必须有实现**：空回调被上层直调会以 `epc=0`（跳 0 地址）崩溃；
- 采样格式先固定一种（如 16 kHz 单声道 S16_LE）打通，再谈多格式。采样率不对时先回到已跑通的格式，不要在没定位的情况下硬上；
- 用**字节率**判断是否丢帧（例如 16 kHz/mono/S16 = 32768 B/s），比"听起来正常"可靠；
- 启动慢要查真实原因：可能是缺少显式调度属性、或每次启动做同步目录扫描，而不是内存不足。

## 8. 网络：以太网 (GMAC + PHY)

**阶梯**
1. MAC 时钟/复位；
2. RMII/MII pinmux 引脚映射；
3. 参考时钟选择（外部 PHY 供时钟时要做系统级时钟选择）；
4. PHY 复位（注意有效电平与复位保持时间）；
5. MDIO 读 PHY ID（证明管理通道）；
6. **有界等待自协商**，读 BMSR 判断 link；必要时打印 BMCR/BMSR/ANAR/LPA 诊断；
7. 描述符环 + 对齐缓冲 + cache 安全维护；
8. 注册 netdev；
9. DHCP 取址 → ping → HTTP 请求。

**坑**
- **复位后立刻读 link 必然是 down**：不是失败，是读得早。加有界等待，并把自协商寄存器全部打出来（基本/状态/通告/对端通告）。**对端通告为 0 = 没和对端协商上**，指向线序/对端配置，而不是 MAC 驱动。
- RMII 的 50 MHz 参考时钟通常由 PHY 提供，MAC 侧要正确选择时钟源，否则表现为"寄存器能读、收发包不对"。
- 描述符/缓冲同样要满足对齐与 cache 要求（沿用采集通路验证过的那套带约束的 cache 操作，**不要用厂商那个有 bug 的 helper**）。
- **上层命令可能被配置裁掉**：精简配置会同时关掉 `ifconfig`/`ifupdown` 命令并把网络信息从 procfs 排除，表现为"驱动好了但没有任何工具可用"。要显式把这些命令打开。
- **"命令 help 里有、执行却说 not found"**：内置命令直执行路径可能漏掉索引 0（列表第一项恰恰是它）。这是 shell 集成 bug，不是驱动问题。
- **改 defconfig 后必须干净重建**，增量构建不会刷新 `.config`（见 `debug_playbook.md` 第 6 节）。
- 判定顺序要逐步升级：`ifconfig` 有网卡（device）→ 静态地址 → ping 网关 → ping 外网 → DNS 解析 → HTTP 成功（data）。中间任何一步没到，不要对外说"网络已通"。
- **非对称连通性不等于通**：对端能 ping 通板子、板子却出不了外网，说明只走通了一个方向；ARP 表里出现板子也只证明板子发得出去。这类情况要写出"到哪一步为止"，不要笼统写"已联网"。

## 9. 网络：SDIO Wi-Fi

**阶梯**
1. Wi-Fi 模组供电 GPIO（常有独立电源控制）；
2. SDIO 总线在线：CMD5 探测；
3. dump CCCR/CIS，确认功能与厂商；
4. 使能功能 1、设置块大小；
5. CMD53 块模式读写验证（证明数据面）；
6. 固件下载：分块发送 → 回读校验 → 启动固件应用；
7. 固件消息链路：reset / version / stack start / RF 校准 / ME 配置 / MAC start；
8. 建立接口（VIF）、发起扫描、接收扫描结果；
9. 注册 netdev（`wlan0`）→ `ifup` → 数据面。

**坑**
- **先判断卡的类型**：枚举完成后读 OCR，若"功能数 > 0 且 memory 位为 0"，说明这是**纯 I/O 卡**，不要套用存储卡的 CMD2/CSD 流程。
- **不要在每次读信息时重跑完整探测**：重复的完整 probe 会复位总线，第二次 CMD5 直接超时。探测结果要有状态缓存。
- **命令返回忙/进行中不等于卡返回错误**：某些"失败"是因为漏了等待响应完成的步骤，命令状态停在"进行中"。先补全响应等待，再怀疑卡。
- **按器件能力选择传输模式**：功能寄存器的位会说明支持哪些模式（例如不支持 byte mode）。发起了不支持的模式就会超时；改成块模式并设置块大小计数。
- **固件下载要回读校验**：分块大小要保证每块是单次块传输；下载后读回首字/校验值确认真的写进去了，再发启动命令。
- **长耗时命令的等待要够长，并且要清干净迟到的响应**：等待太短会失败，而迟到的响应会污染下一条命令，产生"下一条也错"的假象。用有界轮询 + 丢弃残留响应。
- **连接/扫描参数**：扫描用通配 BSSID + 全频道才能拿到目标 AP；固定 BSSID/单信道可能只收到信标。连接确认事件里要检查状态码与中心频率。
- **不要停在"手工命令能跑"**：用户态命令（如 `wapi` 之类）只是外壳，真正的能力需要一个 netdev + 驱动 ioctl + 后台 RX 泵。先有 `wlan0` 再谈上层命令，否则会长期停留在手工调试状态。
- **`ifconfig <if> up` 不等于驱动 up**：有的实现不会触发驱动的 open 回调，还会先给一个临时地址；要用专门的 up 命令，并确认地址/DHCP 真的生效。
- 发送路径的 host 描述符布局必须按厂商二进制实现来定：可能出现"以太头被剥离、`packet_len = len - 14`、ethertype 用网络字节序"这类细节。**移植厂商驱动时以反汇编/实测为准**，不要只照抄头文件。发重复的以太头会导致 DHCP 拿不到地址。
- 接收路径要按实际帧解析：SDIO 头 + 私有 rx 信息 + 802.11 帧的**偏移和长度都要实测确定**（不同固件版本会有差异），QoS 数据帧里 LLC/SNAP 的位置也要单独处理。
- **内存是硬约束**：几份 KB 级静态接收缓冲就能把 BSS 推高到装不下；同时开多个上层功能（重连 + 无线工具 + 私有 ioctl）可能直接链接溢出。先算预算，再决定静态还是动态分配。
- 把固件头内联进工程，去掉对厂商源码树的路径依赖；开机自动 bringup + netreg，并默认安静日志。
- 上电/复位时序与 SDIO 时钟分频要按模组要求；初始化失败时先确认供电，再确认总线。

## 10. 上层：LVGL / UI 应用

**阶梯**
1. framebuffer 与 input 设备都已稳定（先跑通色条与 `getevent`）；
2. 启用 LVGL 与 NuttX 后端，直接映射已有 framebuffer（不要新建第二个）；
3. 内存池与刷新周期按板子配置；
4. 触摸走 touchscreen 后端，方向键/键盘走 keypad 后端；
5. 先跑最小页面，再叠加控件；
6. 统计各类事件计数（touch/dpad）验证交互确实生效。

**坑**
- 轻量配置下**默认背景是透明的**：只设置背景色不生效，填充区域要显式设为 `LV_OPA_COVER`。
- 刷新与 cache：确认 framebuffer 的 cache 维护方式；每帧重提交显示引擎配置会导致闪烁，改为开机配置一次。
- 事件类型选择影响可用性：某些控件用"点击完成"事件容易漏，改用"按下"事件并配合优先级分层更可靠。
- 对象数量要控制：上百个小对象会拖慢刷新，改成单个自绘对象并限制帧率。
- 初始化层若依赖 pthread，**不要为了省资源把它关掉**；其初始化线程栈要够大（实测不足会直接失败）。
