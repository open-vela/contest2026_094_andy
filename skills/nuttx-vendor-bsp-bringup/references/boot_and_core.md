## 1. 启动入口与地址一致性

BSP 的第一类事故不是代码错，而是**地址错**：启动介质按一个地址加载，代码却链接到另一个地址。

一条链上至少有 4 个地址，必须两两一致：

| 位置 | 含义 |
|------|------|
| 链接脚本的段起始（如 `ORIGIN`） | 链接器开始放段的位置 |
| 实际入口符号地址（`__start`） | ELF 里 `_start`/`__start` 落点 |
| 打包描述文件（`.its`/`image_cfg`）的 `load`/`entry` | 启动器从存储搬到内存的地址、跳转地址 |
| 转换后 raw 二进制首地址 | `objcopy -O binary` 产物第一条指令的位置 |

实战教训（D13x）：
- 链接脚本目标 `0x30044000`，但链接器把 `.note.gnu.build-id` 放在最前，`__start` 实际落在 `0x30044100`；打包时 `objcopy ... -R .note` 又删掉该段，**raw 二进制首字节就是 `0x30044100`**，而 `.its` 里写的还是 `load=0x30044000`。结果代码被加载低 `0x100`，启动器跳过去就跑飞。
- 修法：`.its` 的 `load`/`entry` 统一为 `0x30044100`。
- **入口地址以 objcopy 之后的二进制首地址为准，不能只看 ELF entry。** 改过链接脚本的段顺序、保留区或对齐后，必须重新核对一遍。

自查方式：
```bash
riscv-none-elf-readelf -h nuttx | grep 'Entry point'   # ELF 入口
riscv-none-elf-objcopy -O binary nuttx nuttx.bin
riscv-none-elf-objdump -D nuttx.bin | head            # 反汇编首条指令地址
cmp <(printf ...) 或用 hexdump -C nuttx.bin | head     # 首字节机器码
```
把反汇编首地址、`.its` 的 `load`、启动日志里跳转后的 PC 三者对齐。

另外：
- 启动介质往往有硬性布局约束（例如 SPI NOR 启动时 BROM 只认最前面若干个固定大小分区；加载地址要避开 SRAM 最前面一块），照抄同系列配置前先查手册。
- 打包脚本可能"吃旧产物"：不清 `prebuilt`、缺文件不报错、按 `.config` 猜芯片名。**始终显式传参**（板名 + 芯片名），并在打包后核对产物时间戳/哈希。

## 2. 第一条汇编探针

在没有任何日志时，先证明"启动器真的跳到了我们的入口，且串口基址正确"：

```asm
/* _head.S 最前面，第一条指令 */
    li   t0, UART0_BASE
    li   t1, 'S'
    sw   t1, 0(t0)        /* THR 偏移 0，不依赖栈/gp/CSR/C 运行时 */
```

- 打出字符 = 跳转地址对 + 串口基址对 + 串口时钟/引脚已被前级配好。
- 收不到字符时，按顺序排除：跳转地址 → 串口基址 → 串口时钟/复位 → pinmux → 波特率。
- 这一步不要调用任何 C 函数、不要用锁、不要读状态位。

## 3. 中断控制器

中断这一层有两个"静默死"的坑：基址写错、以及把不兼容的开关当成通用开关。

要点：
- **CPU 外设基址（core timer / CLIC / PLIC）写错不会报错**，只会让定时器初始化访问非法 MMIO 然后挂死。核对 SoC 手册的基址，并确认头文件宏（如 `CPU_BASE`）派生出的 `CORET_BASE`/`CLIC_BASE` 是预期值。
- **`mcause` 可能带高位**（level/priority 编码），直接 `mcause & 小掩码` 得到的"IRQ 号"会 ≥ `NR_IRQS`，表现为 trap 里死循环、`ecall` 与中断都不派发。修法：先取低位（如 `& 0x3FF`），再按内核规则加异步中断基偏移。
- **不要套用语义不同的 Kconfig select**：某些"HAVE_CLIC"选项的含义是"关中断改用某 CSR"，而目标 CLIC 是内存映射寄存器。选错会让第一条 `zalloc` 就卡死（反汇编可见 `csrrw ...,0x347` 之类的 CSR 访问）。去掉该 select、回到标准 `mstatus.MIE` 后正常；反过来再打开又能复现，这就是最好的反证。
- **中断模式要匹配内核的派发方式**：CLIC 的向量模式（每个中断独立入口）需要向量表；如果内核走公共 `mtvec → exception_common → dispatch`，就必须用非向量模式。官方中断号本身通常是对的，别急着改号。
- **不要把"配置里没开的选项"当成缺失**：某些看名字"应该开"的选项（尤其与中断控制器相关的 `ARCH_RV_*` 选择）在目标核上可能是**故意关闭**的——通用内核里它的实现语义与目标硬件不同，打开会导致启动与上下文恢复失败。动手前先查项目文档、代码注释和提交历史；"打开后故障能稳定复现"比"名字看起来应该开"是更强的证据。
- 挂接顺序：先 `irq_attach()` 再 `up_enable_irq()`。

## 4. 系统 tick

- 先确认 tick 源：core timer（CLINT/CLIC 自带）还是普通定时器；两者基址与频率来源不同。
- 频率不对的表现是调度节奏错乱、`sleep/usleep` 偏差大、NSH 偶发卡死，而不是"完全不动"。
- 早期 `nx_start` 之后的"无输出"经常不是串口问题，而是 tick/中断基址错导致在 `clock_initialize()` 里挂死——此时连 serial 都还没注册，看起来像串口坏了。

## 5. heap 与 SRAM 布局

链接脚本里要同时明确：`.text/.data/.bss`、栈、堆的边界。常见问题：

- **手写 `.stack` 与内核默认堆起点重叠**：通用 RISC-V 的 `up_allocate_heap()` 可能从 `g_idle_topstack` 起算，和你手工放的 `.stack` 冲突。
- 链接脚本必须导出内核期望的符号（`_sheap`/`_eheap` 或等价物），并加 `ASSERT` 保证堆不小于下限。
- **启动堆耗尽是常见故障**：SRAM 被静态/应用占满时 `_sheap` 可能等于 `_eheap`，表现为启动或某命令一跑就出小偏移的访存 fault（例如现场读到空结构体的某个成员）。处理：关掉占用大的测试应用、留出余量，并加**链接期最小堆断言**把问题提前到构建阶段暴露。
- `CONFIG_RAM_START`/`CONFIG_RAM_SIZE` 要与链接脚本一致。
- 排查栈问题时不要只看容量：**先确认崩溃现场的 `sp` 是否真落在该任务的栈区间内**。出现过 `g_running_task` 是 NSH、而 `sp` 却在 idle 栈里的情况——那不是栈大小问题，而是上下文保存/恢复被污染。
- 高风险项：内核配置 `select` 了 FPU/LAZYFPU，但工具链实际按无 FPU ABI 编译；上下文保存/恢复只动浮点寄存器，会污染整数 trap frame。改这类 `select` 后必须**干净重建**再验证。
- 外扩内存（PSRAM 等）要确认**实际容量**与用途：常见做法是操作系统仍跑在片上 SRAM，外扩内存只做显存/大缓冲，**不进 heap**。

## 6. 早期串口与 console

早期串口要"能出字"，正式串口要"能交互"，这是两件事。

早期（`up_putc` 路径）：
- 直接写 THR，**不加锁、不等状态位**。早期 `spin_lock_irqsave()` 之类不可用；某些状态下 TX 状态位不可靠。
- **不要重配已经由前级（SPL/bootloader）配好的串口**：自己再配 CMU/pinmux 反而把它弄坏。board early 阶段先跳过完整的板级初始化。

正式（NSH 能打字）：
- **只出不进的典型原因**：上层 `write()` 等 TX 缓冲排空，而排空依赖不可靠的 TX 完成状态位，又没有可用的 TX 中断。做法是让 `txint(true)` 直接调用发送轮询函数（同内核里 `serial_cmsdk` 的处理），把数据推出去。
- 核对 `SYSLOG_DEVPATH`、console 设备名与驱动实际注册的节点一致（曾出现日志指向 `/dev/ttyS1`，而驱动只注册 `/dev/ttyS0`）。这类不一致**要改的地方不止一处**（defconfig 里可能同时有 console 与 syslog 两个配置）。
- 注意 canonical 模式：有的 `uart_register()` 强制 `ICANON|ECHO`，交互输入需要非 canonical 逐字符模式。
- 记录下串口参数（基址、THR 偏移、TX/RX 引脚与复用号、时钟寄存器、波特率）写进 skill 笔记，后面每加一个外设都能复用。

## 7. 异常定位

- 异常处理里要能打印：`mcause`（IRQ 号）、`epc`、`ra`、`sp`、定时器值、当前 TCB。
- 拿到 `epc` 后**用反汇编定位**，不要靠猜：`objdump -d nuttx | grep -A/-B <epc>`，或 `addr2line -e nuttx <epc>`。
- 非法地址 trap（如 instruction access fault）配合 `epc/ra` 里的低位地址，通常说明跳到了未初始化/被覆盖的函数指针。
- 每次崩溃都记录：现象、`mcause`、`epc`、`sp`、对应源码行、根因、修法——这是后面写回归清单的原料。

## 8. 探针纪律

- 可以用 `--wrap`/临时打点做插桩，但**绝不要包住异常处理与调度核心**（上下文切换、软件中断入口、调度器恢复等）：会改变栈与返回路径，造出"假崩溃"，把排查带偏。
- 诊断打印本身会扰动时序（尤其串口接收/返回路径），定位完成后**必须全部移除并重新验证一次**。
- 每轮只改一个变量。改完记下"改前现象 → 改后现象"，避免多个假设混在一起。
