# 同系列芯片迁移：怎么复用、哪些必须重写

> 场景：目标芯片在 openvela/NuttX 里还没有适配，但**同系列的另一颗芯片已经有一份实现**（例如 D12x → D13x、A 系列 → B 系列）。
> 这份文档给的是"复用纪律"：哪些可以照抄，哪些必须逐项重定，以及怎么避免把前一颗芯片的假设带过来。

## 1. 先分清两种参考

| 参考类型 | 来源 | 用途 |
|----------|------|------|
| **芯片参考** | 厂商 SDK / 同芯片的 Linux/Zephyr/Bare-metal 驱动 | 校验寄存器地址、位定义、初始化序列、时序 |
| **骨架参考** | NuttX/openvela 里同类驱动，或同系列的已有适配 | 学架构、回调、注册方式、板级初始化顺序 |

两者不能混用：**寄存器值只能来自目标芯片的手册/厂商代码，架构只能来自内核约定。**
同系列的实现两份价值都有，但它的寄存器值只对它的那颗芯片成立。

## 2. 必须重写的东西

**芯片层（chip）必须自建。** 同系列芯片的 chip 层往往看起来能直接用，实际包含大量硬编码：

- 启动汇编：复位入口、`mtvec` 设置、栈、BSS 清零——直接对应地址与布局；
- 中断层：中断控制器的**基址**、中断号到内核 IRQ 的映射、异常派发；
- 时钟/reset 表：每个外设的时钟源、分频、门控位、复位位；
- SoC 定义头：外设基址、IRQ 号、GPIO 分组与编号规则；
- 向量/内存布局文件：可能把 SRAM/外部内存区间写死；
- 厂商扩展指令/CSR：同系列不同核可能支持度不同（工具链里可能就是 Unsupported），要收敛到通用路径。

**板级（board）可以抄骨架，但值必须重定**：
- `board_early_initialize`/`board_late_initialize` 的结构、pinmux/sys_clk 的写法、链接脚本框架、defconfig 的组织方式 → 可复用；
- 引脚、时钟频率、外设地址、控制台串口、内存区间 → 必须按新板改。

**头文件不要软链**：把同系列的头文件（`chip.h`/`irq.h`/SoC 头）直接软链过来，会把旧芯片的地址与中断号一起带进来。**拷贝到自己的目录再逐项改**。

**bootloader/镜像不可想当然**：不同官方板的 bootloader 二进制哈希不同，不是"通用"的。入口/加载地址、分区布局都要按新板确认。

## 3. 可以直接借用的东西

- 内核框架的接入方式：upper-half 的回调签名、`register_*()` 调用、`board_late_initialize()` 注册顺序；
- 通用工具与算法：CRC32、分区解析、私有参数、pinmux 工具；
- 厂商 HAL 的**调用姿势**（不是寄存器值）：先开时钟、再去复位、再配置、再使能；
- 测试应用的写法：一个命令覆盖一个外设、带边界检查与 `PASS/FAIL`。

**复用同系列 HAL 时的规则**：把它当成"参考实现"，逐个寄存器与手册核对；发现不一致以手册为准，并在代码注释里写下差异原因。

## 4. 差异对表方法

开工第一步（S0）产出一张差异表，只覆盖 bringup 必需项：

| 项目 | 同系列（参考） | 目标芯片 | 差异/结论 |
|------|----------------|----------|-----------|
| CPU 核 / ISA / 扩展 | | | 工具链 `-march/-mabi`、FPU/CSR 支持 |
| 中断控制器 | | | 基址、模式（向量/非向量）、IRQ 映射 |
| 系统 tick 源 | | | 基址、频率 |
| RAM/外部内存 | | | 起始、容量、保留区、用途 |
| Flash/启动介质 | | | 启动分区约束、加载地址 |
| UART/I2C/SPI/SDMC/LCD... | | | 基址、时钟、复位、引脚 |
| 时钟树 | | | 源、分频、门控 |
| reset 位 | | | 位号与顺序 |
| GPIO 分组/编号 | | | 组号、IRQ 号 |
| 引脚复用表 | | | 每引脚功能号 |

产出两张清单：
1. **可复用文件**（结构可抄）；
2. **必须重写文件**（值相关）。

这张表后面每加一个外设都会用到，是"少返工"的关键。

## 5. 共享头文件的处理

- 同系列的共享头如果按旧芯片写死（例如 `#ifdef` 只判 D12X），要改成新旧可切换，或直接把目标芯片的副本放到自己目录；
- 改共享头时注意**不要破坏参考芯片的构建**；
- 优先级：能在自己目录里解决就不动公共头；必须动公共头时走 fork + PR，并在差异表里记一笔。

## 6. 踩过的具体坑

- **中断控制器的"HAVE_CLIC"不是通用的**：某选项的语义是"关中断改用 CSR"，而目标核的 CLIC 是内存映射寄存器，选上后第一条 `zalloc` 就卡死；去掉即恢复，重新打开又复现。
- **CPU 外设基址写错是静默死**：核定时器基址写成 `0x20004000`（应为 `0xE0004000`），tick 初始化访问非法 MMIO，表现为"`nx_start` 之后没有任何输出"。
- **`mcause` 高位**：带 level/priority 编码，直接取小掩码会得到越界 IRQ 号，trap 内死循环；要先取低位再按内核规则加异步偏移。
- **中断模式不匹配**：参考实现用了向量表，而内核走公共 `mtvec` 派发，必须改成非向量模式。
- **地址链不一致**：链接脚本/ELF/打包描述/raw 二进制四个地址对不上，代码被搬到错位置（详见 `boot_and_core.md`）。
- **外部内存容量按同系列假设**：实际封装与容量不同（如 8MB 而非 16MB），要按手册确认再定内存布局。
- **FPU 相关配置 select 与实际 ABI 不一致**：会影响上下文保存/恢复，且改完必须干净重建才看得到效果。
- **Kconfig select 改了但没重新展开配置**：增量构建下 `.config` 还是旧值，造成"改了没用"的假象。
